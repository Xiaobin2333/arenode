# 数据库备份和 AI 站点巡查

管理端新增「数据库备份」和「AI 站点巡查」，配置、执行、审核接口仅超级管理员可用。默认均不开启定时任务，AI 默认人工审核，自动禁用默认关闭、阈值 90%。定时任务按小时设置间隔（1–720 小时），保存开启后若无历史任务会在下一次调度执行；调度间隔约 15 秒。任务在数据库中排队，多实例共享工作锁，单次只执行一个任务，进程中断的任务标记失败，不自动重放危险操作。

## S3 备份

配置 HTTPS S3 Endpoint（AWS 可留空）、Region、Bucket、专用前缀、Access Key ID、Secret Access Key 和 Path Style。先保存，再测试连接。连接测试检查桶可访问；首次实际备份验证上传和清理权限。

建议专用桶或前缀，凭据仅授予该范围的 ListBucket、GetObject、PutObject、DeleteObject、AbortMultipartUpload 权限。开启桶版本控制可增加误删除恢复能力，但旧版本存储费用与清理由桶生命周期策略管理。

使用 PostgreSQL 18 客户端执行一致性 `pg_dump` 自定义格式备份；完整备份加密后上传（AES-256-GCM），清单包含 SHA-256 和 HMAC 签名。应用配置中的 S3 / AI 密钥另行加密保存。必须离线保管 `SETTINGS_ENCRYPTION_KEY`，丢失或更换后，旧备份无法解密或列出。不要将密钥放进同一个备份桶。灾后在新实例配置原密钥、桶和前缀即可从 S3 枚举并还原备份。

普通备份保留最近 N 份（1–365）；还原前自动生成的 `pre_restore` 备份不计入 N，也不会自动删除，需要管理员手动清理。清理失败不使已完成的备份失效，任务结果会包含警告。每份最大 1–102400 MiB，默认 1024 MiB。临时磁盘至少预留备份大小的两倍及 PostgreSQL 还原所需空间。

## 覆盖当前数据库

1. 停止所有外部数据库写入工具、脚本和旧版本应用，将本版本应用缩至单实例。应用实例启动前持有 PostgreSQL 共享会话锁；还原升级为独占锁，多实例时拒绝执行，新启动实例在还原结束前不能初始化数据库。
2. 选择备份，填写当前超级管理员密码和 `RESTORE 备份ID`。密码不进入任务或审计记录。
3. 先下载并验证签名、大小、散列、GCM 标签和归档格式，再进入维护状态，暂停计费调度，等在途请求和后台对账结束（最多 60 秒）。若无法排空则取消还原。
4. 自动生成一份还原前备份，失败则不执行覆盖。使用 `pg_restore --single-transaction --exit-on-error --clean --if-exists` 覆盖当前数据库；数据库还原命令失败则事务回滚。
5. 成功后注销所有会话、删除 API 密钥、取消旧排队任务、使缓存失效并重启应用。用备份中的账户重新登录并重新创建 API 密钥。配置和计划任务也回到备份时点。Docker 的 restart 策略应为 `unless-stopped` 或 `always`；非容器运行需进程守护器。

还原提交后若后处理失败，保持维护并重启，任务会尽可能标记失败；这不表示数据库事务回滚。检查已恢复的数据及 S3 中的还原前备份。还原不会回滚 CDNFly 上游、邮件或支付系统等外部状态，管理员须对账。备份仅包含业务数据库，不含 PostgreSQL 全局角色、外部文件、Redis 或上游配置。仅使用相同版本或已验证兼容版本的应用进行还原；降级还原前先验证 schema 兼容性。

## AI 巡查

接口地址填写 OpenAI 兼容根地址，例如 `https://provider.example/v1`，服务端调用 `/chat/completions`，要求支持 JSON mode (`response_format: {type: "json_object"}`)。密钥仅服务器使用，留空保存表示保持原值。模型、补充规则、类别、抽样页数、定时间隔与自动禁用阈值可配置。

可按网站 ID 或巡查全部站点。每个域名从 HTTPS 首页开始，最多抽取 1–5 个同源页面，不执行 JavaScript。抓取限制公网 IP、标准端口、重定向次数、文本类型、大小和时间；每次解析所有 DNS 结果并固定实际连接地址，拒绝私网及重绑定。图片、视频、登录页、通配符域名或动态页面不在完整覆盖范围，检查失败不代表安全。

类别为赌博、色情、诈骗、钓鱼、其他涉嫌违法，以及未发现违规/无法确定。模型须提供页面原文引用，服务端核验引用确实存在；保存引用、URL、页面散列、模型、分类、置信度和理由，不保存整页。页面内容会传送到管理员配置的 AI 提供方，设置前确认该服务的数据处理政策。

置信度是模型估计，不是已校准概率或法律认定。默认管理员查看证据后禁用；只有主动开启自动禁用且属于选中类别、达到阈值才自动执行。禁用先建立隔离记录，再调用上游；上游失败保留隔离，防止其它接口误启用。普通租户接口、管理站点编辑以及套餐自动恢复均不能解除隔离。重新启用必须在巡查页面填写审核理由，并通过客户状态与套餐检查；新一次巡查为正常不会自动解除旧隔离。

最近 100 个任务和 200 条巡查记录在界面显示；历史记录保存在数据库中。任务按串行队列处理，大规模站点巡查可能延后其它任务。可在审计日志中追踪手动任务及禁用/启用操作。
