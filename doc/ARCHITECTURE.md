# Arenode 架构与实现说明

本文说明 Arenode 的系统边界、数据职责、租户隔离和主要实现约束，供部署者、维护者与贡献者参考。

## 1. 设计原则

- 只实现 CDNFly 用户 API 或本地 PostgreSQL/Redis 能完整支撑的能力。
- 页面入口必须对应可用的后端闭环；不展示占位按钮、模拟支付或不可执行的配置。
- PostgreSQL 保存业务事实和不可变流水，Redis 只用于缓存、限流、短期状态和请求合并。
- 资金、订单、续费、兑换和退款必须事务化、幂等、可审计。
- 保持现有接口兼容；列表接口新增分页元数据，不删除原有字段。
- 管理员只保留“超级管理员”和“管理员”两级。

## 2. 明确边界

以下能力不属于 Arenode 的安全功能边界，也不会在客户界面展示：

- CDNFly 上游 API 密钥原文查看或导出、上游账号资料和上游实名认证管理。
- 共享上游账号的全局日志、全局聚合用量和跨客户资源。
- 域名跨上游账号转移。
- “AI 风控”“虚拟租户”“租户隔离”等不准确概念。
- 未配置真实供应商的短信、手机号绑定、支付宝、微信和银行卡支付。
- CDNFly 用户 API 无法可靠完成的写操作。

当前支付方案为余额充值码和管理员资金调整。未来选定支付供应商后，再接入支付下单、签名回调、幂等、关单、退款和对账；在此之前不显示支付渠道入口。

## 3. 数据与一致性基础

- [x] 支持多个 CDNFly 普通用户 API 上游，凭据使用 AES-256-GCM 加密存储且不回传浏览器。
- [x] 平台套餐必须映射启用的上游套餐，购买和管理员分配时把映射冻结到客户套餐。
- [x] 网站、安全资源、四层转发、日志、任务和用量按资源所属上游账号路由。
- [x] 上游资源 ID、缓存键和请求预算按上游账号隔离，相同原始 ID 不冲突。
- [x] 跨上游网站、转发和关联安全资源迁移在上游写入前拒绝，要求重新创建。
- [x] 存在生效客户套餐时禁止停用上游；在售平台套餐引用时禁止停用上游套餐。

- [x] 套餐增加续费失败时间、宽限期结束时间和最后续费时间。
- [x] 订单保存商品名称、价格、周期、额度和权益的购买时快照。
- [x] 自动续费订单使用唯一幂等键，避免定时任务重复扣款。
- [x] 退款关联原订单和反向钱包流水，历史资金流水不可修改。
- [x] 充值码增加批次、活动名称、生效时间、失效时间和批次统计。
- [x] 仅保留必要的邮件发送结果和本地审计；工单、站内通知和通知中心不实现。
- [x] 登录会话保存 IP、设备、创建时间、最后活动时间和到期时间。
- [x] 为客户、站点、订单和审计查询补齐索引。
- [x] 使用 PostgreSQL advisory lock 保证多实例只有一个计费任务执行。

验收：并发购买、续费、兑换和退款不会重复扣款或生成重复权益；多实例定时任务不会重复执行。

## 4. 账号与安全

- [x] 管理员角色仅保留超级管理员和管理员。
- [x] 超级管理员可创建、停用、重置管理员并调整管理员级别。
- [x] 必须始终保留至少一个可登录的超级管理员。
- [x] 普通管理员不能修改超级管理员、管理员列表和高风险运行参数。
- [x] 用户和管理员均支持 TOTP MFA，包含绑定确认、登录验证、恢复码和解绑。
- [x] 登录连续失败达到阈值后临时锁定账号，并写入审计日志。
- [x] 用户和管理员可查看登录会话并撤销指定设备。
- [x] 修改密码、管理员重置密码后撤销全部旧会话。
- [x] 注册开关、邮箱验证和 Turnstile 保持相互独立。
- [x] 开启 Turnstile 时，验证通过后才允许发送邮箱验证码。
- [x] 验证码按邮箱和 IP 分别执行发送间隔与小时上限。
- [x] 使用电子邮件域白名单和可选邀请注册模式；不实现邮箱/IP 二次拒绝规则。
- [x] 注册页增加服务条款与隐私政策同意，服务端验证同意状态。
- [x] 管理员审计日志支持动作、操作者、对象、IP 和日期筛选；平台不提供 CSV 导出。

验收：所有高风险管理操作均有权限校验和审计；关闭对应开关时注册流程不会要求未启用的验证步骤。

## 5. 套餐、订单与资金闭环

- [x] 新用户注册和管理员创建客户均不自动分配套餐。
- [x] 余额购买成功后订单立即完成，无管理员确认状态。
- [x] 支持对现有套餐手动续费，延长原套餐而非创建重复实例。
- [x] 自动续费在到期时原子检查余额、扣款、生成订单并延长有效期。
- [x] 自动续费余额不足时进入可配置宽限期，并按已配置的邮件渠道发送提示。
- [x] 宽限期内定时重试；成功后自动恢复，宽限期结束后暂停相关资源。
- [x] 到期、低余额、超限暂停、额度恢复和同步失败仅写入本地状态/审计；不提供站内通知中心。
- [x] 用户可开关每个套餐的自动续费。
- [x] 订单详情展示商品快照、支付方式、资金流水和套餐实例。
- [x] 管理员可对已支付订单执行一次全额退款，生成反向余额流水。
- [x] 余额调整必须填写原因并二次确认；不允许余额变为负数。
- [x] 充值码支持批量生成、一次性显示、搜索、停用和核销记录；平台不提供 CSV 导出。
- [x] 权益兑换码与余额充值码在命名和页面上保持明确区分。

验收：续费、退款和充值均能从订单追溯到钱包流水；任何失败不会产生半完成订单或半生效权益。

## 6. 运营与财务管理

- [x] 客户、站点、客户套餐、订单、钱包、充值码、用量和审计统一服务端分页。
- [x] 所有列表支持关键词、状态和日期筛选，必要列表支持排序。
- [x] 客户详情集中展示资料、验证状态、余额、套餐、站点、订单和登录记录。
- [x] 订单详情展示完整快照和关联流水。
- [x] 站点详情只展示用户 API 可读写的基础配置、回源、HTTPS、缓存、安全、监控和日志能力。
- [x] 用量继续归入“运营管理”，显示统计周期和最后同步时间。
- [x] 财务管理提供收入、消费、退款、人工调整、充值和余额负债统计。
- [x] 财务报表支持日期范围查询；平台不提供 CSV 导出。
- [x] 充值码批次支持生成量、核销量、到账金额和剩余次数统计。
- [x] 后台概览改用聚合查询，不再加载全部客户和全部明细计算统计。

验收：十万级订单、客户和流水下，任何管理页面都不会整表返回或静默截断。

## 7. 公告与运行配置

- [x] 公告支持级别、受众、开始时间、结束时间和是否弹窗。
- [x] 运行参数增加维护模式、邀请注册、续费宽限期、余额告警阈值和用量告警阈值。
- [x] SMTP 提供发送测试邮件；Turnstile 提供配置测试，测试成功后才允许启用。
- [x] 提供公开的服务条款、隐私政策和联系邮箱配置；不实现客服工单中心。
- [x] 系统状态显示 PostgreSQL、Redis、CDNFly、定时任务和邮件状态，仅管理员可见。

验收：公告在时间和受众范围外不会显示；维护模式不影响管理员登录；站内通知和工单入口不存在。

## 8. UI 与文案

- [x] 用户导航：概览、网站管理、用量与监控、套餐与购买、余额与订单、账号安全。
- [x] 管理员导航：运营管理、套餐管理、财务管理、系统管理、安全与审计、系统状态。
- [x] 购买、退款、余额调整、停用和删除使用正式确认弹窗，不使用浏览器原生 confirm/alert。
- [x] 购买确认显示商品、金额、有效期、目标套餐和支付后余额。
- [x] 列表提供加载骨架、空数据、错误和重试状态。
- [x] 移动端表格改为紧凑列表或固定关键列，不只依赖横向滚动。
- [x] 使用统一图标体系，图标按钮提供 tooltip 和可访问名称。
- [x] 注册和找回密码按钮始终可见；未完成验证时显示明确禁用状态。
- [x] 邮箱验证码按钮保持在邮箱输入框右侧，长倒计时不能撑破布局。
- [x] 增加密码显示切换、强度提示和字段级错误。
- [x] 图表显示时间范围、最后更新时间、空状态和数据来源。
- [x] 管理员导航支持搜索并记住展开状态。
- [x] 删除普通用户页面中的 PostgreSQL、Redis 和内部缓存术语。

统一文案：

- “注册控制台”改为“创建账号”。
- “重置登录凭据”改为“找回密码”。
- “套餐需自行购买”改为“注册成功后可使用余额购买套餐”。
- 管理端统一使用“客户套餐”。
- 财务统一使用“余额充值码”，并与“权益兑换码”区分。
- “同步用量并执行限额”改为“同步用量并检查额度”。
- 超限说明改为“超出套餐额度后，相关网站和转发将暂停；额度恢复后自动恢复”。
- “平台安全”改为“安全与审计”。

## 10. 实施顺序

1. 数据模型、事务幂等和多实例任务锁。
2. 续费、公告、退款和充值码批次。
3. 两级管理员、MFA、登录与会话安全。
4. 分页查询、客户/订单详情和报表。
5. 公告、法律页面和运行配置测试。
6. 用户端和管理员端 UI 统一改造。
7. 自动化测试、浏览器验收、文档和部署验证。

每一阶段完成后先运行相关测试，再进入下一阶段；发现上游 API 无法可靠完成的功能时，从 UI 中移除，而不是保留不可用入口。
